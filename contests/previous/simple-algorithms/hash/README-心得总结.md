# 哈希思想与计数数组

> 本目录共 **9** 个题解文件，由 `basics / implementation / brute-force / greedy` 中挑选出的代表性题目组成。

## 一、这一类题在考什么

这里的"哈希"是广义的——**用桶 / 数组 / 哈希表把"值"映射成"下标或计数"**，这是把 O(n²) 压到 O(n) 最常用的手段。

## 二、关键思路与套路

- **计数数组 / 桶**：CF806B（26 位桶：首次出现的题得 2 分、之后每次 1 分）、CF799B（统计频次后只保留偶数部分）、CF686B 是同型题。
- **因子计数**：CF693A（统计 w、h 中因子 2 的个数，答案 = 2^(两者之和)）。
- **按值域建桶后分类讨论**：CF898B（有 0 就给某个 0 加 1，否则给最小值加 1，使总乘积最大）。
- **哈希表存字符串做匹配**：CF644F（把候选串与其他串逐一比对，用哈希/集合加速查找）。
- **分段标记 + 计数**：CF786D（按分隔符分段，用计数标记每段内字符是否同时出现）。
- **值 → 位置的映射**：CF1089B（用"p[i] ≤ i 则代价为 0"这一性质做贪心，靠计数判定可行）。
- **候选值枚举 + 集合去重**：CF1098C1 / CF1098C2（枚举第一个不同的数位，其余位贪心填最小/最大合法数字）。
- **数位和分桶**：ECF188E（枚举首位与长度，用数位和区间校验，配合计数）。
- 与 `data-structures/stl` 的区别：这里关注"**用什么做键、怎么把问题降到线性**"，那里关注容器 API 与工程细节。

## 三、最容易踩的坑

- 键的设计决定成败：能直接用值当下标就别用 `map`；用 `map` 时避免用 `[]` 访问不存在的键（会插入默认值，导致统计出错）。
