## 决策二：`prefix-sum` 和 `difference` 放在 `math` 下，不搬到 `simple-algorithms`

**结论：两者都留在 `math/`。**

**理由：**

1. **它们几乎总是"服务于别的算法"**，而不是能独立成题的基础工具。看目录内容就清楚：16 个前缀和题里，6 个是在优化 DP 转移、3 个是在配合二分、1 个是加权容斥的高难度题。`simple-algorithms` 里的 `sort` / `hash` 是"看到题就能对号入座"的独立技巧，而前缀和/差分是**附着在具体题目上的预处理层**——按使用场景归到 math 更贴近实际。
2. **互为逆运算，放同一父目录才有对照价值**。你新建 `difference` 的直觉是对的（差分单独成类），而它和前缀和是同一个技巧的两面，拆到两个顶层目录会让"互逆关系"这个最重要的学习点散掉。
3. **math 里已经有 `number-theory`、`combinatorics`、`patterns`，正好构成"数学基础 → 计数 → 找规律"的递进**，前缀和/差分作为"序列预处理"补在最前面（它们是所有 DP / 计数的地基），逻辑闭环。
4. **代价很低**：`math` 已经有 `README-目录总览.md` 做导航，8 个子目录一眼能看完，不存在"太深找不到"的问题。

**什么情况下我会改变这个判断**：如果将来 `simple-algorithms` 里也出现"前缀和模板题"（纯粹只考 `pre[r]-pre[l-1]`），那类题可以考虑放 `simple-algorithms`，而把"用于优化/计数的前缀和"留在 math。目前没有这种题，所以不用拆。

## 决策三：`math/patterns` **保留**，但缩小定位

**结论：保留，但把"数方案数"的题移走。**

**理由：**

1. 「找规律 / 找不变量 / 手玩小数据推结论」是一项**独立的、无法被其他目录覆盖的能力**。看它的内容：`CF1122D`（不变量 `a[i]-i`）、`CF1114C1/C2`（奇偶位计数充要条件）、`CF640C`（每 n-1 个一组的公式）、`CF1086A`（抽屉原理）—— 这些题既不是构造、也不是贪心、更不是数论，只能放在"规律"里。
2. 但它确实**混进了两类不该在这里的题**，本轮已移走：
   - 「数方案数」类 → `math/combinatorics`（`LGP8865` 种花、`CF1122C`）；
   - 「用前缀和/差分」类 → `math/prefix-sum`（`CF993H`、`LGP2727`、`CF971F`）。
3. 移完之后 `patterns` 剩 14 题，主题变得纯度更高：**不变量、奇偶性、抽屉原理、分类讨论、手动找公式**。
4. 我也把它的 README 重新写过了，开头明确写了"定位：只收靠找规律/不变量推结论的题"，并说明了哪些题已被移到别处 —— 以后你加题时可以照着这个边界放。

## 决策四：新建 `math/combinatorics`，**不取代** `patterns`

**结论：新建，与 `patterns` 并存。**

**理由：**

1. **两者考的能力不同**：组合数学考"**数清楚有多少种**"（乘法原理、组合数、容斥）；patterns 考"**发现结论**"（不变量、奇偶性）。前者有明确的公式与工具链（杨辉三角、逆元、容斥），后者没有通用方法论。混在一起会导致"想练计数时找不到题、想练找规律时被计数题淹没"。
2. **为什么不用组合数学取代 patterns**：patterns 里真正属于计数的只有 3 题左右，其余 12 题（`CF640B`、`CF640C`、`CF644C`、`CF693C`、`CF940A`、`CF971C`、`CF1086A`、`CF1086B`、`CF1090C`、`CF1114C1/C2`、`CF1122D` 等）都不是计数。若用 combinatorics 取代 patterns，这些题就无处可去，只能硬塞进 greedy 或 constructive，反而破坏现有分类。
3. **组合数学值得单独存在**，因为它是**后续进阶的必经之路**：`math/fast-power` 里学到的逆元、`dp/linear` 里学到的计数 DP、`math/number-theory` 里学到的容斥，都需要 combinatorics 这个"汇合点"。你的题库里已经有 `LGP2727`（杨辉三角 + 逐位确定）、`LGP8865`（NOIP2022 种花）、`CF1122C`，加上 `dp/linear` 里的计数 DP，这条线迟早要成体系。
4. **目录会不会太碎？** 目前 `math` 有 8 个子目录（prefix-sum 16、number-theory 15、patterns 14、combinatorics 2、bitwise 4、geometry 3、difference 2、fast-power 1）。子目录多但每个都有明确主题，且 `math/README-目录总览.md` 有导航表，我认为是**可以接受的"适度细分"**，比把所有数学题堆在一个目录里更好找。
5. **combinatorics 现在只有 2 题，会不会太薄？** 会 —— 所以我在它的 README 里写了"下一步该补什么"（容斥、卡特兰数、错排、卢卡斯定理）。**建议的补题来源**：以后遇到下列题就往里放 —— 数方案数、数子序列/子集、数路径、带模逆元的组合计算。如果你觉得 2 题太少，可以先把它当"占位目录"，或者告诉我，我把它合并回 patterns 也行。

## 一句话总结

**前缀和与差分一起放 `math`（它们互为逆运算、且多数时候服务于 DP/计数）；`patterns` 保留但收窄到"找规律"；另建 `math/combinatorics` 专收计数题，取代不了也不该取代 `patterns`。**
